## 一、目标形态（北极星）

一句话描述想要的成品体验：

> **只给一个大纲，其余全自动跑完一本漫画。**

拆解成链路就是：

```
大纲
 └─▶ 酒馆扩写成正文
      └─▶ AI 分镜 + AI 选画框（每页版式）
           └─▶ 写每一格的 tag
                └─▶ 定每一格用到的 LoRA 与正/负面
                     └─▶ 发送 ComfyUI 逐格出图
                          └─▶ 每格结果自动接进漫画编辑器
                               └─▶ 自动拼接成整页 → 成册
```

并且**全程可切换**：

- **AI 全自动**：一键从头跑到尾，中途不停。
- **人工**：每个阶段停下来，人工审、改、通过。

## 三、待做需求（可按编号当 issue）

### R1　前端「一键自动跑完整本」按钮　【高】

**目标**：在「流水线」页放一个显眼的「▶ 一键自动跑」按钮，点了之后自动按 S1→S6 依次跑完，不用人工一个个点。

**要点**：

- 后端新增一个"编排作业"（或编排服务）：按阶段顺序驱动，前一阶段完成才进下一阶段；
- 需要**自动满足审查门**：编排时临时按 `auto` 逻辑放行，或直接以"产物即通过"策略推进；
- **进度实时回报**（复用现有 SSE `/api/jobs/events`），前端能看到"现在在跑第几阶段/第几格"；
- **可随时取消**（复用 `/api/jobs/{id}/cancel`，要能中断正在跑的 ComfyUI 生成）；
- 跑完给出结果入口（PDF/CBZ 下载）。

**现状缺口**：`autodrive.py` 具备编排逻辑，但①是命令行脚本、②需要手动指定项目、③S1 正文要酒馆标签页、S5 要 MED 静态服务占用，尚未做成"后端可调用 + 前端一键"。

### R2　S1 正文的全自动（去掉"必须有人盯酒馆"）　【中】

**目标**：全自动模式下，S1 正文也能无人值守生成，不要求人工在酒馆里逐段点。

**要点**：

- 目前正文靠酒馆扩展在浏览器标签页里生成（`comic-bridge` + 常驻桥 `tools/tavern_bridge.py`）；
- 全自动时需：自动触发"开始写作"，按目标页数/篇幅自动**续写**到足够长度，并自动"通过"以便 S2 能启动；
- 续写目前有前置约束（前面段落需全部通过才允许续写），自动模式下要能自动放行。

### R3　配置集中化　【中】

**目标**：把散落在多处的配置收拢到**一个「设置」中心**，一处可查全、可见地分层。

**现状**：配置散落在这些地方（见第五节明细）——`config/*.yaml`、`.env`、数据库表、项目字段、前端 localStorage。用户经常找不到"我要改的这项在哪"。

**要点**：建议按**作用域**分层呈现：

- 全局（连接类）：LLM 供应商、ComfyUI 后端、SSH 隧道；
- 项目级：目标页数、审查模式、选图策略、每格批量张数、项目画风 LoRA、酒馆绑定；
- 阶段级：S2/S3 提示词模板、阶段→供应商绑定、工作流参数映射；
- 资产级：角色卡、正/负向预设；
- **每项标注"改这里是全局还是只影响本项目"**，并支持一键跳到修改位置。

### R4　左侧菜单重构　【中】

**目标**：让左侧导航一眼能看懂"我现在该去哪一步"。

**现状问题**：8 个平铺菜单（项目/正文/流水线/分格/提示词/出图/分页合成/设置）里，既有"阶段"又有"工具"，层级混在一起，新人容易迷路。

**要点**（建议，非强制）：

- 按阶段分组呈现：**写作（正文）→ 分格 → 提示词 → 出图 → 合成 → 导出**，用阶段序号串起来；
- 「项目」「设置」这类**非阶段**入口单独归到一侧（如顶部/底部）；
- 显示每步的**完成状态/待办徽标**（如"分格 ✓、提示词 3/16"），让"下一步该点哪"自明；
- 「流水线」页与左侧导航的职责分清（一个是全局看板，一个是分步操作）。

### R5　各阶段产物都能在界面上直接编辑　【中】

**目标**：**每个阶段的产物**都能在界面上直接编辑；改完生成**新版本**（不覆盖旧版），并沿血缘把下游自动标 `stale`，可只重跑受影响的部分。

**现状（部分已实现）**：

| 产物 | 现在能不能编辑 | 入口 |
|---|---|---|
| S1 正文段落 | ✅ 可编辑 | 「正文」页每段的「编辑」 |
| S2 分格脚本 | ✅ 可编辑 | 「分格」页每页「编辑/换模板」 |
| S3 每格提示词 | ✅ 可编辑 | 「提示词」页每格「改 / 改这格」 |
| S4 候选图 | ⚠️ 只能换图/重出，不能改参数后重出 | 「出图」页候选图库 |
| S5 整页 | ⚠️ 只能去 MED 里改，没有"改这条产物"的入口 | MED 工作台 |
| S6 导出物 | ❌ 不能编辑 | — |

**要点**：

- 做一套**统一的产物编辑面板**：按产物类型（kind）渲染对应表单，而不是每个页面各写一套；
- **编辑即新版本** + 血缘标 stale + 提供「只重跑受影响的下游」按钮；
- 补齐缺口：S4 支持"改参数后按此格重出"、S5 支持前端直接改（或明确跳转 MED）、S6 可重导出。

### R6　各阶段调用的系统提示词调优　【高】

**目标**：S2 分页分格、S3 分镜提示词**实际发给 LLM 的系统提示词与用户提示词模板，目前是初版、未针对真实模型调优**，需要成体系地优化并版本化。

**现状**：提示词放在 `backend/prompts/s2_script.md`、`backend/prompts/s3_prompt.md`（前端「提示词模板」可临时覆盖，存 `prompt_overrides` 表）。这两份是"能跑通"的水平，没有做过对比、没有针对具体模型（如 DeepSeek/Kimi/智谱）的措辞打磨。

**要点**：

- 建一套**评测/对比方法**：用同一份大纲、同一个模型，跑不同提示词版本，横向对比产物质量（分格合理性、每格 tag 的可用率、画风一致性）；
- 把验证有效的改动**固化回 `backend/prompts/*.md` 默认值**（而不是只留在某人的本地覆盖里），并记录版本；
- 说明 S1 正文的提示词不在这里：它由**酒馆的角色卡/世界书/预设**决定，调优 S1 等于调优酒馆预设；
- 后续可考虑分供应商维护不同措辞（不同模型吃不同的提示词风格）。

## 四、优先级建议

| 顺序 | 需求 | 理由 |
|---|---|---|
| 1 | **R1 一键自动跑** | 是"目标形态"的核心差异点，也是最想先要的 |
| 2 | **R6 提示词调优** | 直接决定成品质量，越早开始越好 |
| 3 | **R4 菜单重构** | 影响所有人每天的使用手感，改动相对独立 |
| 4 | **R3 配置集中** | 降低"找不到配置"的挫败，为后续扩展打底 |
| 5 | **R2 S1 无人值守** | 依赖酒馆/桥的稳定性，可与 R1 并行推进 |
| 6 | **R5 全阶段产物可编辑** | 提升精修效率，与现有编辑能力衔接 |

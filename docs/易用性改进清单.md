# 易用性改进清单

> 持续更新：2026-10-14。按独立批次实现、验证和提交本地 Git，每批可回滚。
> 开发分支：`codex/usability-workbench`；基线：`07559e2`。

## 产品方向

把大纲到成册的六阶段流程做成连续工作台：明确当前项目、阶段状态与下一步，常用编辑留在当前页面，配置和高级操作分层收纳。

参考 [novelai_local_web](https://github.com/YILING0013/novelai_local_web) 的 [漫画工作区](https://github.com/YILING0013/novelai_local_web/blob/main/docs/comic-workspace.md)：借鉴工作区内选页、编辑、独立画框参数和保存反馈的交互组织，结合本项目的 ComfyUI、产物版本和审核机制实现。

## 现状发现

- 左侧八项入口平铺，项目管理、阶段操作、全局设置混在一起；看不到完整的 S1–S6 路径。
- 导出阶段已有后端处理器，前端却只有流水线上的运行按钮，没有格式选择、页序预览和 PDF/CBZ 下载中心。
- 「去 MED 合成」「继续编辑」打开新标签页，保存后再跳回前端。现有同源桥已经具备 iframe 编辑能力，可复用。
- MED 桥页面面向自检，状态 JSON、示例按钮占用编辑空间，不适合直接作为日常编辑工作台。
- 供应商、出图连接、角色资产、画风和系统提示词分散，缺少二级菜单和作用域说明。
- 项目切换后的页、合成、导出视图刷新和上下文提示需要统一，避免看到上一个项目的内容。
- 流水线的「全自动」目前只表示自动审核，不能等同于一次点击持续驱动所有阶段。

## 编辑器选择

先复用 MED：保留已接通的模板、图层、气泡、画布存档、自动贴图和后端合成，通过现有桥嵌入主工作台。

参考项目的漫画编辑器有自己的前端、浏览器存储和画框生成流程。直接替换需要适配模板几何、项目与页标识、画布文档、ComfyUI 参数、产物版本、审核和无头导出，范围明显大于消除新标签跳转。A2 先完成内嵌体验，替换留作后续独立评估。

## 验证边界

开发核对使用临时配置、临时数据库和模拟外部生成，不启动会执行历史回填的真实应用 lifespan，也不写真实项目的配置或产物。

页面与 MED 交互尽量使用本地实际静态资源；没有可用的外部 ComfyUI/LLM 时明确记录模拟验证的范围，不把模拟成功作为真实出图质量结论。
